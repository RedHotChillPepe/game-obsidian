# 1. Итог (рекомендация)

> **Рекомендация: Unreal Engine 5.8, архитектура «C++ в первую очередь».** Вся игровая логика пишется на C++ (её удобно писать и править с Claude Code). Blueprints используются только для тонкой склейки: анимационные графы, настройка ассетов, катсцены. Демо делаем на 5.8 без миграции. Решение о переходе на UE6 принимаем после получения финансирования.

**Почему UE5:** жанр и цель демо (впечатлить инвесторов картинкой) плюс встроенные системы, которые закрывают наши ключевые механики: массовый ИИ (Mass), ИИ-деревья (StateTree / Behavior Tree), Gameplay Ability System, Motion Matching, физика Chaos, Nanite и Lumen. Крупные soulslike последних лет — Black Myth: Wukong и Lords of the Fallen (2023) — сделаны на UE5.

**Когда стоит выбрать Unity:** если в первые 2–3 недели станет ясно, что C++ и долгие компиляции UE тормозят команду сильнее, чем помогает готовая графика. У Unity быстрее цикл итераций, C# проще, а Claude Code работает с ним особенно уверенно. Проверить это можно двухнедельным «пробным спринтом» в обоих движках (раздел 6).

# 3. Сравнение по требованиям проекта

Оценки от 1 до 5. Вес — важность критерия для нашего демо.

!widths 26,7,8,8,51
| Критерий | Вес | UE 5.8 | Unity 6 | Комментарий |
|---|---|---|---|---|
| Картинка «из коробки» (тёмное фэнтези, свет, туман) | 5 | 5 | 3 | Lumen, Nanite, объёмный туман. В Unity сопоставимое качество требует больше ручной настройки HDRP |
| Ближний бой soulslike: анимации, хитбоксы, root motion | 5 | 5 | 4 | В UE есть Motion Matching, GAS, Montage, много готовых шаблонов soulslike на Fab. В Unity боевые системы чаще собираются из ассетов |
| Рои и батальоны (сотни врагов) | 5 | 4 | 3 | UE: Mass Entity + VAT-анимации (Niagara / AnimToTexture). Unity: ECS быстрый, но официальной ECS-анимации нет (в дорожной карте она в статусе «Planned»), нужны сторонние решения |
| Отсечение конечностей | 4 | 4 | 4 | В обоих движках делается своими силами (разрезанные меши, скрытие костей, физика) или готовыми плагинами |
| Адаптивный ИИ босса | 4 | 4 | 4 | Основа — свой код (модель игрока, utility AI) в обоих движках. Для ML: UE Learning Agents (экспериментальный), Unity ML-Agents (зрелее, версия 4.0.x поддерживается) |
| Симуляция живого мира, NPC | 3 | 4 | 4 | В обоих движках — свой код. В UE есть Mass для «фоновых» NPC и StateTree |
| Работа через Claude Code (текстовый код) | 5 | 3 | 5 | C# проще и компилируется быстро. C++ в UE с макросами и долгой сборкой; Blueprints — бинарные, ИИ их не правит. Решается подходом «C++ в первую очередь» |
| Порог входа для команды без опыта движка | 4 | 2 | 4 | UE сложнее, особенно C++. Unity быстрее осваивается |
| Консоли PS5 / Xbox Series | 4 | 5 | 4 | Оба движка поддерживают консоли. Доступ к SDK в обоих случаях — через программы Sony и Microsoft. У UE больше AAA-опыта на консолях |
| Производительность на консолях с большим числом врагов | 4 | 4 | 4 | Зависит от архитектуры больше, чем от движка |
| Стоимость | 3 | 5 | 4 | UE: 0 до $1 млн выручки. Unity: Pro обязателен после инвестиций |
| Стабильность платформы на 2–3 года | 3 | 3 | 4 | UE: переход на UE6 в 2027–2028 — неопределённость. Unity: линейка 6.x развивается постепенно |
| Впечатление на инвесторов | 4 | 5 | 3 | «Сделано на UE5» и уровень картинки работают на питч |

**Взвешенный итог:** UE 5.8 — **≈ 4,3**, Unity 6 — **≈ 3,8** (сумма «оценка × вес», делённая на сумму весов 53). Разница небольшая: решает приоритет картинки, роёв и soulslike-инструментов против скорости разработки.

# 4. Как UE5 закрывает наши механики

| Механика | Инструменты UE5 | Что пишем сами |
|---|---|---|
| Бой | Gameplay Ability System (GAS), Animation Montages, Motion Matching, Enhanced Input | Комбо, стойкость, парирование, хитбоксы по частям тела |
| Увечья и протезы | Skeletal Mesh (скрытие костей, модульные части), Chaos Physics, Control Rig, анимационные слои | Компонент состояния тела, смена наборов анимаций по тегам GAS, система протезов |
| Рой и батальоны | Mass Entity / Mass AI, StateTree, Smart Objects, Niagara, вершинные анимации (VAT), Environment Query System | Координатор группы, токены атак, мораль, бюджет угрозы, LOD ИИ |
| Адаптивный босс | Behavior Tree / StateTree, EQS, (опционально) Learning Agents | Профиль игрока, предсказатель, utility-выбор атак, память между смертями |
| Живой мир | Mass для фоновых NPC, World Partition, SaveGame | Журнал событий, память NPC, слухи, симуляция «тиков» при отдыхе |
| Поселения | Data Layers / Level Instances (состояния деревни), PCG (процедурная расстановка) | Конечный автомат поселения, бегство NPC |

> **Про число врагов.** Независимое исследование Mass Entity (2026, Politecnico di Torino, предварительные результаты) показало около 800 полностью симулируемых агентов на тестовом железе. Рои в тысячи особей делаются гибридом: Mass/упрощённая логика + анимация на GPU через VAT. Цели демо (50–150 врагов в кадре) реалистичны, но **их нужно подтвердить прототипом в первые 2 месяца**.

# 5. Технологический стек

| Задача | Инструмент | Примечание |
|---|---|---|
| Движок | Unreal Engine 5.8 | Зафиксировать версию на весь цикл демо |
| Язык | C++ (логика), Blueprints (склейка) | Правило: никакой игровой логики в Blueprints |
| IDE | JetBrains Rider или Visual Studio 2022 | Rider удобнее для UE |
| ИИ-ассистент | Claude Code + MCP-сервер для UE | MCP — по выбору после проверки (сообщество, разный уровень зрелости) |
| Контроль версий | Git + Git LFS (или Perforce) | Perforce — стандарт для UE, но Git проще для команды из двух человек; LFS обязателен для ассетов |
| Задачи | GitHub Projects / Trello / YouTrack | Достаточно простой доски |
| Документация | Word-документы (эта папка) + Markdown в репозитории | Канон и GDD |
| Анимации | Паки Fab, Mixamo (прототипы), Cascadeur, аутсорс, мокап-библиотеки | Анимации — главный узкий ресурс soulslike |
| 3D-ассеты | Fab (в т. ч. Megascans), Unity Asset Store (паки с поддержкой UE) | Брать 1–2 стилистически совместимых автора |
| Диалоги NPC | Системная память + банк реплик, сгенерированный LLM при разработке (Claude Code) | LLM внутри игры — только опциональный эксперимент для PC после демо (см. документ 01, раздел 3.4) |
| Звук | Встроенный MetaSounds или FMOD / Wwise | Проверить условия бесплатных лицензий для малых бюджетов |
| Тестирование | Unreal Automation / Functional Tests, автотесты логики на C++ | Тесты для состояний тела, морали, выбора атак |
| Аналитика плейтестов | Свои логи сессий (JSON) + таблицы | Нужна для настройки адаптивного босса |
| Сборки | Unreal Automation Tool, скрипты сборки, позже CI | Ночные сборки для тестеров |

# 6. План проверки выбора (2 недели, до начала препродакшна)

Чтобы не выбирать вслепую, рекомендуется короткий пробный спринт.

| Задача | UE 5.8 | Unity 6 |
|---|---|---|
| Персонаж с камерой, перекатом, лёгкой атакой (из ассетов) | ✔ | ✔ |
| 100 простых врагов, бегущих к игроку (Mass / ECS + VAT) — замер FPS | ✔ | ✔ |
| Отсечение руки у манекена (скрытие кости + физическая часть) | ✔ | ✔ |
| Claude Code: сгенерировать и подключить компонент «Состояние тела» | ✔ | ✔ |

**Критерии выбора:** скорость прохождения задач, стабильность, качество картинки, насколько комфортно работать с ИИ-ассистентом. Если UE не хуже по скорости более чем в 1,5 раза — берём UE.

# 7. Альтернативы, которые рассматривались

- **Godot 4.** Бесплатный и открытый, удобен для ИИ-ассистентов (всё в тексте). Но экспорт на PS5/Xbox идёт только через сторонние компании, мало готовых AAA-ассетов, слабее инструменты для роёв и высококачественной графики. Для нашего демо не рекомендуется.
- **Собственный движок** — исключено для команды из 2 человек.

# 8. Решения и риски, связанные с движком

| Риск | Что делаем |
|---|---|
| UE6 выйдет в ранний доступ в 2027, UE5 перестанет получать крупные обновления | Демо на 5.8. Код пишем модульно (логика отдельно от движковой «обвязки»), чтобы облегчить миграцию |
| Долгая компиляция C++ мешает итерациям | Live Coding, модульная структура, логика баланса — в данных, а не в коде |
| Claude Code не может править Blueprints | Архитектура «C++ в первую очередь», MCP для операций в редакторе |
| Качество MCP-интеграций от сообщества | Не завязывать критичный процесс на MCP, использовать как ускоритель |
| Megascans платные | Заложить бюджет на ассеты, использовать бесплатные ежемесячные раздачи Fab |
